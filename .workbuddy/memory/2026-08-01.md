## 更正诊断：并非路由器/本地网络问题（重要）
- 用户在公司已重试仍 `fetch failed`，与"在家"表现一致 → 排除单纯家庭路由器拦截。
- 关键探测：即使用**公共 DNS**（Google 8.8.8.8、Ali 223.5.5.5）解析：
  - `cloudstudio.tencent.com` → **NXDOMAIN（域名不存在）**
  - `agentos-app.net` → **0.0.0.1（域名权威层设置的黑洞地址，全球一致）**
  → 说明 CloudStudio 部署端点是在**域名权威 DNS 层就被置死/停用**，与用户所在网络、路由器规则、机器 DNS 设置均无关。换网络、关路由器规则、改本机 DNS 都救不了。

- 结论：当前 Agent 环境无法通过 CloudStudio 或 htmlcode.fun 生成可用公开链接。旧的 `*.agentos-app.net` 链接因父域 0.0.0.1 大概率也已失效。
