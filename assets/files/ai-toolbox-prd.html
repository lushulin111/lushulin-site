〇、文档导读（给读者/面试官）

这份 PRD 讲的是什么：把摄影教育公司"获客→售前→教学→交付→运营→营销"全链路的 7 个 AI 应用点，合成一个可分批交付的产品规划——摄影教育 AI 工具矩阵。它由两部分组成：共享底座（学员数据 + 课程知识库 + 大模型服务 + 统一账号权限）+ 7 个场景化应用。

这份 PRD 为什么值得看： 1. 每个功能都挂在真实的业务环节上，配有可量化指标，不是空谈产品思维； 2. 模型选型、成本控制、数据评估、合规、AI 输出质量怎么验证，都有明确答案，不是"上个大模型就行"； 3. 配套 7 个能现场演示的 demo 原型，证明这不是纸面方案； 4. 交付路径是分期的：P0/P1/P2 分级清晰，最小可用版 1-2 周能上线。

一、背景与问题

1.1 行业背景

摄影兴趣教育（尤其面向中老年学员）是重服务、重信任、重线下的行业： - 学员付费决策周期长，售前需要极强的"专业感"和"个性化"； - 教学依赖讲师个人经验，质量参差、难以复制； - 学员流失率高（兴趣类课程天然易倦怠），且流失往往发生在"苗头期"却无人发现； - 运营动作大量依赖人工（手写笔记、手查名单、手做海报），效率低、口径不一。

1.2 现状痛点（业务侧调研结论）

环节 现状 痛点
售前转化 销售口述课程体系 无直观材料，学员感知不到个性化
教学执行 讲师手写拍摄脚本/备课 一套脚本半天起，质量靠个人
课后交付 班主任手写课堂笔记 费时、口径不统一、学员感知弱
运营督学 月底人工查流失 发现太晚，话术靠个人发挥
品牌营销 海报找设计排期 出图慢、品牌风格不统一
获客内容 机位攻略散落各平台 无积累、无信任背书

1.3 为什么是现在做

大模型（DeepSeek 等）成本已降到免费/极低水平；所在公司已有成熟的课程体系和学员运营数据。AI 不是从零造内容，是把已有的东西放大。

二、产品定位与目标

2.1 产品定位

一句话：给摄影教育机构内部员工使用的 AI 工作台，把"售前、教学、交付、运营、营销"各环节的重人工工作，变成"点几下就出结果"。

2.2 产品目标（北极星指标 + 分环节指标）

数值均为示意目标值（脱敏处理），用于展示指标设计方法；真实目标以内部版为准。

层级 指标 目标值（上线 3 个月，示意）
北极星 月活工具使用次数（内部员工） ≥ 300 次/月
售前 意向学员 → 规划书发送率 ≥ 80%
售前 VIP 成交转化率 提升 15%
教学 拍摄脚本生成用时 半天 → 5 分钟
交付 课堂笔记覆盖率（每节课） ≥ 90%
运营 学员月流失率 下降 30%（用挽回率验证）
营销 单张海报制作用时 1 天 → 10 分钟

说明：上表目标值是预期，不是现状。指标要有说服力，必须三样东西齐全：现状基线、目标、验证方法。见 2.3。

2.3 指标口径与验证计划

每个指标都标清楚：现状基线从哪来、目标是多少、上线后拿什么验证。标"立项时摸底"的，立项第一周完成摸底并回填本表。

表格内数值为示意，重点看"现状→目标→验证方式"三件套的方法。

指标 现状（摸底基线） 目标（示意） 验证方式
月活工具使用次数 无工具，现状为 0；立项时摸底员工现状工作流 ≥300 次/月 埋点统计（打开/生成/导出计数）
规划书发送率 销售靠口述，无发送记录；立项时摸底 ≥80% 埋点 + 抽查销售跟进记录
VIP 成交转化率 立项时拉历史成交数据定基线 +15% 试点班对比（用工具 vs 不用）
拍摄脚本生成用时 手写约半天（4 小时）；立项时向讲师确认 ≤5 分钟 埋点计时
课堂笔记覆盖率 手工笔记，覆盖不稳定；立项时摸底 ≥90% 每节课记录 vs 笔记产出数
学员月流失率 立项时拉历史流失数据定基线 -30% 试点班对比；挽回率=恢复打卡人数÷预警人数
单张海报制作用时 设计排期约 1 天；立项时向运营确认 ≤10 分钟 埋点计时
关怀话术效果 现靠班主任人工发挥，无基线；试点班摸底 挽回率 ≥30% 试点对比（1 班用/1 班不用）；样本够时做 AB 测试（模板话术 vs AI 个性化话术）

验证计划说明： 1. 埋点方案与数据收集机制见第八章，本表是业务指标口径，两者配套； 2. 试点是主要验证手段：选 1 个班用工具、1 个班不用，对比周期 2-4 周（内部员工样本量小，不适合直接跑正规 AB 测试，用试点对比代替）； 3. 话术、文案这类"两种做法哪个好"的问题，当样本量足够时用 AB 测试解决，先看试点数据再决定是否上 AB。

2.4 产品边界（明确不做）

  • 不做学员端 App/小程序（P2 再说）；
  • 不做全自动触达（学员微信自动推送，P1 再评估）；
  • 不做教学内容的 AI 全自动生成（AI 只辅助讲师，人工终审）。

三、目标用户与使用场景

3.1 用户画像（内部员工，7 个工具的使用者）

角色 部门 使用工具 核心诉求
课程顾问 销售 学习规划生成器 快速出专业规划书，提高成交
讲师 教学 拍摄脚本生成器、作品点评 备课提效、作业点评标准化
班主任 运营 督学预警、课堂总结 盯流失、出笔记，省时间
运营/市场 运营 海报生成器、机位分享 快速出图、内容获客
教研 教学 全部（内容生产） 课程素材积累
管理层 决策 数据看板 看挽回率、转化率等经营指标

3.2 关键使用场景（用户故事）

US-01（售前）：作为课程顾问，当学员咨询时，我希望输入学员年龄/时间/设备/兴趣，
    自动生成一份个性化学习规划书，以便 3 分钟内发出专业材料促成成交。

US-02（教学）：作为讲师，当我需要备一节日系拍摄课时，我希望输入风格词自动产出
    含服装/动作/机位/器材的完整脚本，以便备课从半天缩短到几分钟。

US-03（运营）：作为班主任，当我每天早上打开工作台时，我希望系统自动列出今日
    预警学员（黄/橙/红）并生成关怀话术，以便第一时间跟进防流失。

US-04（交付）：作为班主任，当老师上完课时，我希望导入逐字稿自动生成课堂笔记
    （学员版+内部版），以便 1 分钟完成课后交付与留档。

US-05（营销）：作为运营，当我需要一张双十一海报时，我希望填文案选模板即可
    导出符合品牌规范的成品图，以便不再排队等设计。

四、产品架构

4.1 总体架构（共享底座 + 场景应用）

┌─────────────────────────────────────────────────────┐
│                  应用层（7 个工具）                    │
│  学习规划 │ 拍摄脚本 │ 作品点评 │ 督学预警 │ 课堂总结   │
│  海报生成 │ 机位分享                                   │
├─────────────────────────────────────────────────────┤
│                  服务层（共享能力）                    │
│  账号权限 │ 学员档案 │ 课程知识库 │ 内容模板库 │ 数据统计 │
├─────────────────────────────────────────────────────┤
│                  模型层（大模型服务）                  │
│  文本生成（DeepSeek 等）│ 图像生成（生图 API）│ 转写服务 │
├─────────────────────────────────────────────────────┤
│                  数据层                               │
│  学员数据（出勤/打卡/作业）│ 课程数据 │ 内容数据 │ 日志数据 │
└─────────────────────────────────────────────────────┘

4.2 为什么这样分层

  • 底座共享：学员档案/课程知识库是所有工具的数据源（学习规划要课程名、督学预警要出勤记录、课堂总结要课程版本），共享底座避免数据孤岛；
  • 模型可替换：模型层抽象成统一服务，当前用规则引擎兜底、免费模型降本，后续可换更强模型，应用层不用动；
  • 渐进式交付：每个应用独立上线，先做投入产出比最高的，不需要整体一起做。

五、功能需求（按工具拆分）

优先级定义：P0=上线必须有（最小可用版）｜P1=上线后 1-3 个月｜P2=3 个月以后 每个工具附：核心用户故事、功能清单、验收标准、AI 实现要点、指标

5.1 学习规划生成器（P0 · 售前转化）

用户故事：见 US-01。

功能清单： | 编号 | 功能 | 描述 | 优先级 | |---|---|---|---| | LP-01 | 学员信息采集 | 问卷式表单：年龄/空闲时间/有无相机/熟悉度(0-5)/兴趣(多选)/学习目标/过往经历 | P0 | | LP-02 | 四维诊断 | 基础(熟悉度→阶段处理)/兴趣(→侧重主题)/时间(→总周期)/设备(→购机建议) | P0 | | LP-03 | 规划书生成 | 8 大板块：画像摘要/学习目标/缺口分析/三阶段总览/分阶段周计划/针对性建议/设备工具/节奏建议 | P0 | | LP-04 | 购机引导 | 无相机学员：预算分档推荐 + 引导话术（机型以公司主推为准） | P0 | | LP-05 | 导出分享 | 导出 Markdown / PDF，可直接发学员 | P0 | | LP-06 | 学员档案留存 | 生成记录存档、进度追踪、销售跟进记录 | P1 | | LP-07 | 规划书人工微调 | 生成后讲师可改再发送 | P1 |

验收标准： 1. 输入模拟学员（62 岁阿姨/28 岁上班族/40 岁进阶男）→ 输出 8 板块完整规划书； 2. 熟悉度≥4 时阶段一跳过、2-3 压缩、≤1 完整，规则判定正确； 3. 无相机学员必须含购机建议板块； 4. 所有课程名引用真实课程库，不出现占位课名； 5. 导出 PDF 直接下载不弹打印框。

AI 实现要点：诊断规则用结构化规则引擎（可解释、不产生幻觉），不依赖大模型做判断；规划书文案用大模型生成；课程名从课程知识库注入 prompt（禁止自创课程名）。

指标：规划书生成耗时（分钟）、发送率、成交转化率。

5.2 拍摄脚本生成器（P0 · 教学执行）

用户故事：见 US-02。

功能清单： | 编号 | 功能 | 描述 | 优先级 | |---|---|---|---| | SC-01 | 风格输入 | 16 个内置风格关键词 + 自由输入兜底 | P0 | | SC-02 | 脚本生成 | 8 大板块：风格解析/服装搭配/动作引导/地点/时间/器材光线/构图镜头/道具妆发/调色/易错点 | P0 | | SC-03 | 服装日常化 | 服装强制为日常可购款（白T/牛仔/碎花裙等），禁止概念款 | P0 | | SC-04 | 参考图生成 | 3 套服装图 + 1 张动作 6 宫格图 | P0 | | SC-05 | 器材分级 | 相机版 + 手机版双版本参数 | P0 | | SC-06 | 镜头表 | 分镜头脚本含镜头语言/参数/模特引导话术 | P1 | | SC-07 | 一键转发 | 脚本转学员群/打印版 | P1 |

验收标准： 1. 输入"日系"→ 产出 8 大板块完整脚本，3 套服装全部为日常款； 2. 动作引导 ≥6 个，每个含模特引导话术； 3. 参考图 4 张（3 服装 + 1 六宫格），风格一致； 4. 陌生风格词不报错，走兜底逻辑产可用脚本； 5. 产出称呼统一用"摄影师"（不出现老师/学员教学口径）。

AI 实现要点：脚本结构用模板约束（输出固定 8 板块，防跑偏）；服装日常化在 prompt 用"正面约束+负面清单"双保险；参考图生图 prompt 加唯一前缀防文件名冲突。

指标：备课用时（半天→5 分钟）、脚本使用率、学员作业完成率。

5.3 AI 作品点评工具（P1 · 交付评作业）

用户故事：作为讲师，当学员上交作品时，我希望 AI 从构图/光线/色彩/技术/创意/后期六维度结构化点评并给出改进建议，以便批量高效评作业且点评质量稳定。

功能清单： | 编号 | 功能 | 描述 | 优先级 | |---|---|---|---| | RV-01 | 作品上传 | 上传照片（支持拖拽/选择） | P1 | | RV-02 | 六维点评 | 构图/光线/色彩/技术/创意/后期逐维度诊断 | P1 | | RV-03 | 亮点肯定 | 先肯定亮点再指问题（专业鼓励型语气） | P1 | | RV-04 | 改进参考图 | AI 生成"改进版"参考图，说明调整点/原因/下次怎么拍 | P2 | | RV-05 | 点评报告导出 | 结构化报告，可存档/发学员 | P1 |

验收标准：上传样张 → 六维点评齐全、先肯定后建议、语言鼓励不打击信心；改进参考图需附文字说明（调整点+原因+下次拍摄建议）。

AI 实现要点：图像理解用多模态模型；点评语气在 prompt 强约束"先肯定后指问题"；六维结构固定输出模板。

指标：单张点评耗时、点评覆盖率、学员满意度。

5.4 督学预警助手（P0 · 运营督学）

用户故事：见 US-03。

功能清单： | 编号 | 功能 | 描述 | 优先级 | |---|---|---|---| | DS-01 | 数据接入 | 学员出勤/打卡/作业/活跃度数据（CSV 导入 → 教务对接） | P0 | | DS-02 | 预警规则引擎 | 5 条规则，阈值可配置、实时生效（缺勤/不打卡/不交作业/活跃度下降/沉睡） | P0 | | DS-03 | 分级预警 | 黄/橙/红三级排序 + 今日待办工作台 | P0 | | DS-04 | AI 关怀话术 | 选中学员一键生成关怀话术（离线模板 / 可接 DeepSeek） | P0 | | DS-05 | 触达闭环 | 待处理 → 已发送 → 已闭环 状态管理 | P0 | | DS-06 | 误报申诉 | 班主任可标记"误报/已请假"，降低系统失信 | P0 | | DS-07 | 学情周报 | 自动生成班级学情周报 | P1 | | DS-08 | 权限隔离 | 班主任只能看自己班学员（隐私底线） | P0 | | DS-09 | 自动触达 | 全自动发微信（需企微/微信通道评估） | P2 |

验收标准： 1. 模拟 15 名学员数据 → 按 5 条规则正确分级（红/橙/黄分布合理）； 2. 选中预警学员 → 生成可复制的关怀话术； 3. 标记闭环后从待办消失、进已处理区； 4. 班主任 A 无法看到班主任 B 班级学员（权限隔离）； 5. 误报可申诉并记录。

AI 实现要点：预警用规则引擎（不依赖 LLM，快且零成本）；话术用模板 + LLM 增强；核心指标"挽回率 = 恢复打卡人数 ÷ 预警人数"。

指标：挽回率、预警命中率（试点 1 班 2-4 周验证）、班主任处理时长。

5.5 课堂总结生成器（P0 · 课后交付）

用户故事：见 US-04。

AI 实现要点：长文本提炼用大模型（DeepSeek）优于规则；"大白话+比喻"语气面向中老年学员硬约束；笔记不承诺学习效果（合规）。

指标：笔记覆盖率、单篇生成耗时、班主任满意度。

六、非功能需求

类别 需求
合规 不承诺学习效果（禁止"保证学会/包教包会"）；收集学员信息（年龄/昵称/微信）需加用途说明；手机号/微信/出勤为个人信息，内部权限管控（班主任只能看自己班）
安全 账号密码登录、角色权限隔离；数据不落地外部（模型调用最小化数据）；日志留痕
性能 单次生成 ≤ 10 秒（文本）；生图 ≤ 60 秒；支持内部员工并发（≤50 人）
可用性 内部员工零培训可用（大白话文案、选择式输入）；移动端可用（班主任手机操作）
成本 文本生成优先免费/低成本模型（DeepSeek），生图接口按次计费；设置月成本上限告警

七、模型与 AI 技术选型

能力 选型 理由
文本生成（笔记/话术/规划书文案） DeepSeek 系列 中文能力强、成本低、可私有化部署
结构化诊断/预警规则 规则引擎（非 LLM） 零成本、可解释、无幻觉，关键业务逻辑不用 LLM 兜底
图像理解（作品点评） 多模态模型（GPT-4o/豆包视觉等） 需真实理解照片构图光线
图像生成（参考图/海报背景） 生图 API（按次计费） 演示版已跑通，正式版接入公司账号
音视频转写（课堂总结 L3） 转写服务（按需） 仅 P2，成本可控

关键决策：规则引擎 vs 大模型 - 预警/诊断/筛选类：规则引擎（确定性强、零幻觉、免费）； - 文案/内容生成类：大模型（质量高、需要"人味"）； - 两者结合：规则定结构，LLM 填内容——演示版已验证此架构（规则提炼 + 模板输出）。

八、数据与 AI 质量评估

8.1 数据埋点（每个工具最小埋点集）

  • 使用类：工具打开次数、生成次数、导出次数、单次耗时；
  • 业务类：规划书发送率、笔记覆盖率、预警命中率、挽回率、海报复用率；
  • 质量类：AI 输出被人工修改的比例（修改率 = 人工改动字段数 ÷ 总字段数，评估 AI 质量的核心指标）。

8.2 AI 质量评估

  • 每次生成记录"原始输出 + 人工修改后输出"，存成评估集；
  • 每两周抽样 20 条人工评分（结构化/准确率/语气/合规），推动 prompt 迭代；
  • 建一份"黑名单输出"清单（如承诺性用语），上线前用自动化用例拦住。

九、迭代路线图

Phase 0（已完成）：7 个单文件演示原型 + POC 汇报 —— 验证可行性、收集需求
Phase 1（1-2 周，P0 集）：督学预警最小版（CSV 导入+规则引擎+话术+权限）
                        + 学习规划（接真实课名+部署）+ 课堂总结（接 AI 接口）
Phase 2（1-3 个月，P1 集）：作品点评、海报生成器、机位分享全国扩展
                        + 学员档案/历史/统计看板
Phase 3（3-6 个月，P2 集）：自动触达、学员端小程序、批量生成、UGC 机位库

上线顺序的决策逻辑（为什么先督学预警/学习规划/课堂总结）： 1. 督学预警：直接作用流失率（钱袋子），最小版 1-2 周可跑，指标（挽回率）老板看得懂； 2. 学习规划：直接作用转化（钱袋子），但依赖真实课程库（业务方配合）； 3. 课堂总结：纯提效无风险、无隐私负担，最快建立员工信任。
